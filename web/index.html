01 / 日常场景

工作中这些事，可以换种做法。

01 / 企业软件开发

订单改了，
发货还在看旧表。

订单、交期和进度分散在几份表里，问到哪一步还得逐个找人。

根据现有做事方式搭建业务系统，把订单、更新记录和负责人放到一起。

发货同事打开订单就能看最新内容；负责人也能看到谁在处理、下一步等什么。

看看订单怎么管理。 ↗ 02 / AI Agent 搭建

资料都在，
问题还是反复问。

制度、产品资料和操作说明散在不同文件里，新同事找不到，熟悉业务的人常常要停下来回答。

把确认可用的资料整理成知识助手，查找常见问题时同时列出来源。

同事可以先查答案、打开原文核对；资料不足时再找负责人，重要答复仍由人确认。

看看知识助手怎么用。 ↗ 03 / 工作流自动化

一份信息，
要填好几遍。

客户提交表单后，还要复制进表格、通知同事，再追着确认有没有处理。

先看现有工具能否连接，再设置收到表单后的记录和提醒步骤。

新表单进来后，信息可以自动记到指定位置，负责同事收到提醒；信息缺失或处理失败时，由负责人检查。

看看重复步骤怎么处理。 ↗ 04 / 网站搭建

客户打开官网，
却看不清能做什么。

业务介绍分散，手机上阅读不方便，想联系时也找不到入口。

先整理服务内容和客户关心的问题，再设计适合电脑和手机浏览的网站。

客户进站后能找到业务介绍、了解服务范围，也能直接看到联系方式。

03 / 合作方式

先把事情说清楚，
再一步步做。

聊聊需求 ↗
  1. 01 / 了解现状

    先聊怎么做事

    看看现在用什么工具，哪一步最费事，谁会使用。

  2. 02 / 确认方案

    把要做的说清楚

    约定功能、范围和验收方式，必要时先用原型确认操作。

  3. 03 / 开发验证

    拿实际场景来试

    按约定节点查看进展，用业务样本检查正常情况和异常情况。

  4. 04 / 验收交接

    交付后知道怎么用

    按约定验收，交接使用说明，并明确后续支持范围。
